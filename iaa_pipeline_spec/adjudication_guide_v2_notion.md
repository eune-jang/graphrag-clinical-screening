## 1. 이 작업이 뭔지

### 합의가 아니라 정답 확정

두 라벨러를 불러 토론시키는 게 아님. 내가 심판이 되어, 아래 §2의 근거 순서대로 정답을 정하고 이유를 기록하는 작업.

왜 합의로 안 되나 — 실제 사례가 있음:

- 진단·병기 나누기에서 EHJ의 덜 쪼갬도, DYK의 5분할도 **둘 다 오답**이었음 (정답은 NCCN 근거 3분할)
- 2라운드에 두 사람이 새로 같은 답에 도달한 항목 중에도, 규칙과 어긋나는 경우가 나옴

→ 일치도(κ)는 "둘이 같은가"만 재고, "맞는가"는 못 잼. 그래서 정답셋이 따로 필요함.

### 내가 라벨러였다는 점

판정자(나)는 이 데이터의 라벨러(EHJ)이자 가이드라인 저자. 6주 넘게 지났어도 판단 버릇은 남아 있음. 그래서:

- 1차 통과는 반드시 **가림 모드**로 (내 예전 답 포함 아무것도 안 보고)
- 진짜 미결 항목(§4의 NCT05756153 E6)은 판정 후 **PI 확인**
- "내가 만든 규칙이 오답을 유도했다" 싶으면 규칙상태에 `conflict`를 솔직하게 기록 — 이게 유일한 자기교정 장치. 61건에서 conflict가 0건이면 그게 오히려 이상 신호

## 2. 판정 기준

### 2-1. 무엇을 보고 판정하나 — 준거 동결

판정 내내 아래 세 문서만 기준으로 씀. **판정 중에는 이 문서들을 고치지 않음** (중간에 고치면 앞뒤 판정의 기준이 달라짐). 고치고 싶은 게 보이면 규칙상태 `conflict`/`gap`으로 적어두고 v1.3으로 넘김.

| 문서 | 역할 |
| --- | --- |
| `ontology_full_specification_unified_v1_2_2_ko.md` + `ontology_spec_v1_2_3_patch.md` | 그래프 구조가 강제하는 것 |
| `annotation_guideline_v1_2_1.md` | 라벨링 규칙 (오늘 동결) |

### 2-2. 근거 등급 (위에서부터 순서대로 적용, 위에서 결정되면 아래는 안 봄)

| 등급 | 근거 | 쉽게 말하면 | 예 |
| --- | --- | --- | --- |
| **0** | 스펙 구조 | 그래프에 그렇게밖에 못 들어감. 논의 여지 없음 | 쪼갰으면 조각 2개 이상 / 쪼갰으면 AND·OR 표기 / **종류가 다른 항목(진단+약물 등)은 한 조각에 못 섞음** |
| **1** | NCCN 등 임상 문헌 | 문헌을 인용하면 끝남 | 절제 가능성은 병기와 별개 축 → 진단·병기·절제 3분할 |
| **2** | CRC 업무 방식 | 내 전문 판단 영역 | 동반질환과 병용약물은 같은 화면이라도 따로 확인 |
| **3** | 결정 불가 | 어느 근거로도 못 정함 → **솔직하게 보류** | gap ticket으로 분리, 정답셋에 안 넣음 |

- 등급 0 중 "조각 2개 이상"과 "AND/OR 표기"는 시스템이 자동으로 잡아줌. **"종류 혼재 금지"는 자동으로 못 잡으니 내가 직접 확인** (자동으로 못 잡는다고 근거가 약한 게 아님 — 가장 강한 근거)
- 단, 혼재 금지는 **말단 조각**에만 적용. 부모(묶음 문장)는 자녀들 종류가 섞여도 정상
- 등급 3을 억지로 정답 처리하지 않는 것이 중요. "못 정했다"는 기록 자체가 논문 재료가 됨

### 2-3. 라벨 4종 (쉬운 정의)

| 라벨 | 쉽게 말하면 | 예 |
| --- | --- | --- |
| composite_split | 서로 다른 조건 여러 개가 한 문장에 | "≥18세 + 치료력 없음 + NSCLC" → 3조각 |
| macro_aggregate | 우산 문장 하나 + 그 아래 세부 항목들 | "Adequate organ function: ANC…, Plt…, Cr…" |
| nested_exception | "단, ~는 제외/허용" 같은 예외 문구 | "additional malignancy **except** basal cell carcinoma" |
| none | 한 번에 판정되는 단일 조건 | "ECOG 0 or 1" |

- child_logic: 쪼갠 경우(composite·macro **둘 다**) 조각이 전부 충족돼야 하면 `AND`, 하나만 되면 `OR`. **항상 적음** (비워두면 "AND 의도"인지 "깜빡"인지 구분 불가). 문장에 쓰인 and/or 단어가 아니라 **실제 의미**로 판정
- 예외 조각(nested_exception의 "except ~" 부분)은 자녀가 아님 → 더 안 쪼개고, AND/OR도 안 붙임

### 2-4. 판정하면서 적는 것

| 입력 | 내용 | 비고 |
| --- | --- | --- |
| 정답 라벨 ★ | 위 4종 중 하나 | |
| 근거 등급 ★ | 0/1/2/3 | |
| 이유 한 줄 ★ | 왜 이 답인지 | ⭐ v1.3의 유일한 재료 |
| 조각별 이유 ★ | 쪼갠 경우, 각 조각을 왜 이렇게 잘랐는지 한 줄씩 | 프롬프트 예시 재료 |
| 규칙 번호 | 근거로 쓴 v1.2.1 규칙 (예: "§3 외부문서위임") | **억지로 못 찾으면 공란** — 그게 발견 |
| 규칙 상태 | 아래 표 | |
| PI 확인 | 임상 판단 필요 시 체크 | |

**규칙 상태 4값 (쉬운 정의)**

| 값 | 뜻 |
| --- | --- |
| `existing` | 라벨링 당시에도 있던 규칙으로 설명됨 |
| `new` | **라벨링 이후에 생기거나 바뀐 규칙**으로 정한 것 — 라벨러 잘못이 아니라 규칙이 정련된 것 |
| `conflict` | 기존 규칙 두 개가 서로 반대 답을 가리키거나, 규칙이 오답을 유도함 |
| `gap` | 어떤 규칙으로도 못 정함 (= 등급 3) |

→ 이렇게 나눠 적어야, 초록에서 "당시 규칙으로도 틀린 것"과 "규칙이 바뀌어서 달라진 것"을 분리해 셀 수 있음. 후자는 오답 통계가 아니라 "규칙 정련의 증거"로 따로 보고함.

### 2-5. 가장 자주 만날 판단 — "재는 도구"인가 "따지는 항목"인가

불일치의 대부분이 "쪼갤까 말까"이고, 그 핵심 구분은 이것:

| 구분 | 뜻 | 처리 |
| --- | --- | --- |
| **재는 도구** (평가 수단) | CBC, biochemistry, resting ECG 같은 검사 이름. 그 자체로 통과/탈락이 안 정해짐 | 조각으로 안 만듦 |
| **따지는 항목** (판정 단위) | ANC ≥1500, 고혈압 유무처럼 개별 ✓/✗가 나오는 것 | 조각으로 만듦 |

- 수치·항목이 본문에 없고 "IB 참조", "Table 참조"뿐이면 → 따지는 항목이 문장에 없는 것 → **none** + notes에 "thresholds delegated to IB" (v1.2.1 §3 외부 문서 위임)
- 우산 문장 아래 실제 항목들이 나열돼 있으면 → macro, 항목 하나당 조각 하나

## 3. 작업 방법

### 3-1. 두 번 통과

**1차 — 가림 모드 ON**: 두 사람 라벨을 아예 안 보고 내 답을 먼저 정함. 저장하면 이 답은 `blind_label`로 영구 보존됨 (나중에 정답을 바꿔도 남음 — 1·2차가 달라진 항목이 그 자체로 분석 재료).

**2차 — 가림 해제**: 같은 항목을 다시 열면 두 사람 라벨·메모가 보임. 최종 정답 확정. 메모는 전체의 7%에만 있으니 "(no note)"가 정상.

### 3-2. 조각 입력 — 3가지만 기억

1. **원문에서 드래그해서 복사** — 직접 타이핑 금지. 눈에 안 보이는 문자(≥, µ, 특수 하이픈)가 다르면 뒤 단계가 전부 깨짐
2. **떨어진 표현은 이어붙이지 말고 세그먼트로** — `["locally advanced", "Stage III"]`처럼 배열에 나눠 담음. 각 세그먼트는 원문에서 Ctrl+F로 찾아지는 연속 구간이어야 함
3. **공통 표현은 조각마다 복사하지 않음** — 상위 AND 계층으로 표현 (v1.2.1 Text_span (1))

### 3-3. 복잡한 계층 구조를 만나면 — 보류 플래그

"A이고, 그리고 (B1 또는 B2)" 같은 문장은 v1.2.1대로면 여러 계층으로 나눠야 하지만, **이번에는 최상위 라벨 + 직계 조각까지만** 정하고 `needs_recursion` 플래그를 켜둠.

- 이유: 두 라벨러의 라벨이 단층이라, 정답만 계층이면 비교가 안 됨. 초록 숫자는 최상위 라벨만으로 충분
- 플래그 켠 항목은 초록의 오답 집계에서 **제외** (라벨 차이가 아니라 표기 방식 차이라서)
- 마감 후 플래그 목록만 모아 계층 완성 작업을 한 번 더 함

### 3-4. 못 정하겠으면

등급 3 선택 → 이유 한 줄("어느 근거로도 미결") → 자동으로 gap ticket으로 분리됨. 정답셋에 안 들어감. 억지로 답을 만드는 것보다 이게 맞음.

## 4. 순서와 분량

### 4-1. 61건, 이 순서로

| 순서 | 층 | 건수 | 초록에서 쓰이는 곳 |
| --- | --- | --- | --- |
| ① | **해소 15** — 1차엔 갈렸다가 2차에 같아진 항목 | 15 | "합의가 정답으로 수렴했나" [X/15 vs Y/15] |
| ② | **무작위 감사 25** — 계속 일치했던 항목 표본 | 25 | "일치 항목 속 숨은 오답" [X/25] ← 초록 핵심 숫자 |
| ③ | **지속 21** — 두 라운드 다 갈린 항목 | 21 | 갈린 기전 3가지 + LLM 비교 |
| (여유 시) | 위험군 일치 항목 (S2) | ~15 | Methods 서술 정합 |

- ①부터 시작하는 이유: 라벨이 일치했던 항목이라 워밍업으로 적합하고, 판정 감각이 잡힌 뒤 가장 어려운 ③에 들어가게 됨
- ② 감사에서 오답이 나오면: 0건 → 종료 / 1건 → 25건 추가 / 2건 이상 → 50건 추가
- **나중으로 미룬 것** (초록에 안 쓰임): 신규 불일치 13건, 조각 경계만 다른 4건, S2 잔여, 계층 완성, held-out 3라운드

### 4-2. 예전 "최우선 4건"의 현재 상태

v1.2에서 규칙이 정리되면서 4건 중 3건은 **답이 이미 규칙에 있음**. 판정이 아니라 규칙 확인 작업이 됐고, 규칙상태는 `new`(라벨링 이후 정련된 규칙)로 기록.

| 항목 | 상태 |
| --- | --- |
| NCT02474355 I6 (organ function + IB 참조) | v1.2 "외부 문서 위임" 규칙이 이 문장을 예시로 씀 → 규칙 확인만 |
| NCT02474355 E8 (resting ECG) | 같은 규칙의 근거 사례 → 규칙 확인만 |
| NCT03728556 E6 (immune checkpoints) | v1.2 §4 참고가 이 문장을 예시로 유지 → 규칙 확인만 |
| **NCT05756153 E6** (uncontrolled systemic diseases, such as HTN or DM) | **유일한 진짜 미결** — §4의 macro 예시와 §4 참고의 none 예외가 서로 반대를 가리킴. blind로 판정하고 `conflict` 기록 + PI 확인 |

## 5. 하지 말 것

| 금지 | 이유 |
| --- | --- |
| 2:1 다수결로 정답 결정 | 내 blind 답은 세 번째 의견이지 투표권이 아님 |
| 판정 중 가이드라인·스펙 수정 | 앞뒤 판정의 기준이 달라짐 → `conflict`/`gap` 기록으로 대체 |
| 규칙 번호 억지로 채우기 | `new`·`gap` 발견을 놓침 |
| 조각 직접 타이핑 / 임의 정리(공백·대소문자) | 원문 그대로가 원칙 |

| 등급 3을 억지로 정답 처리 | 미결정 기록이 설계 의도 |
| 기존 1·2라운드 파일 수정 | 원자료, 읽기 전용 |
