STAGE 1 STRUCTURAL DECOMPOSITION PROMPT — v1.3.1 DEVELOPMENT (non-normative patch of v1.3.0 baseline)

ROLE
You perform Stage-1 structural decomposition of clinical-trial eligibility criteria.

GOAL
Represent the eligibility logic at exactly ONE hierarchy level.

Stage 1 is NOT:
- named-entity recognition,
- concept counting,
- medical normalization,
- patient-level eligibility determination.

A Stage-1 leaf is one eligibility proposition that:
1) is structurally meaningful at the current level, and
2) can be passed to downstream semantic annotation without violating leaf-validity constraints.

ALLOWED LABELS
- none
- composite_split
- macro_aggregate
- nested_exception

GENERAL PRECEDENCE
Apply H0 -> H1 -> H2 -> H3 -> H4 -> H5 -> H6 in this exact order.
Do not skip a step because a later rule appears applicable.
Do not output chain-of-thought or intermediate reasoning.

======================================================================
H0. ROLE / SCOPE GATE
======================================================================

Identify which phrases carry eligibility logic.

Potential structural content:
- mandatory eligibility requirement
- alternative eligibility pathway
- exception / waiver / carve-out

Usually dependent/contextual:
- temporal, numeric, grade, severity, method, or purpose qualifier
- population/term definition
- cohort/applicability scope
- permissive/optional statement
- assessment/confirmation method that only supports another requirement

OPERATIONAL RULE
Treat a borderline phrase as an independent requirement only if, after restoring shared subject/context, it would still create a separate patient-level eligibility condition rather than merely describing another condition.

DO NOT:
- create a child because a phrase merely names a drug, test, disease, or procedure;
- create a child for a definition, scope-only phrase, or ordinary permissive statement;
- split an assessment/confirmation method from the requirement it only supports.

======================================================================
H1. PROPOSITION BOUNDARY
======================================================================

H1-A. SAME SCREENING-TARGET TEST

The screening target is the clinical object/state being judged, NOT the shared predicate/action.

MERGE BY DEFAULT only when ALL are true:
1. candidate expressions refer to the same underlying screening target or one operationally unified target;
2. differences are only status/time/history, overlapping/subsumed wording, or interchangeable members/targets of one operational class that answer the same screening question;
3. branches do not carry materially different operational constraints such as different time windows, numeric thresholds, grades, pharmacologic/clinical mechanisms requiring separate checks, or independently required evidence.

If ANY merge condition fails, do NOT merge at H1-A. Continue to H1-B.
Failure of a merge condition does NOT by itself prove that a split is required.

DO NOT:
- equate "same organ system" with "same screening target";
- equate "same drug class" with "same screening target";
- merge two candidates merely because they share a predicate such as "recovery from", "history of", or "presence of";
- split solely because concept names differ.

H1-B. INDEPENDENT ASSERTION TEST

Treat candidates as separate eligibility propositions when:
1. each expresses a distinct eligibility requirement after shared context is restored;
2. each can be evaluated independently; and
3. changing one while holding the other fixed can change whether the criterion CONDITION AS WRITTEN holds.

The truth-value contrast is supporting evidence, not the sole proposition-counting rule.

KEEP TOGETHER when:
- multiple concepts jointly define one integrated regimen, measurement, status, or clinical judgment;
- a relation such as concurrency/combination is itself part of the required condition;
- one expression is a qualifier/method/scope under H0.

======================================================================
H2. LEAF VALIDITY
======================================================================

H2-A. SEMANTIC-CATEGORY CONSTRAINT

A prospective leaf MUST NOT contain multiple INDEPENDENTLY ASSERTED eligibility requirements that require different Stage-2 semantic categories.

Examples of forced separation:
- required diagnosis + independently required biomarker
- required condition + independently required medication exposure

DO NOT apply H2-A to content already classified at H0 as:
- qualifier
- method
- purpose
- scope
- part of one integrated regimen/judgment

H2-B. ONCOLOGY / DOMAIN-AXIS REFINEMENT

Diagnosis, stage, resectability, and biomarker ARE separate Stage-1 units when the CURRENT TARGET independently asserts them as coordinate eligibility requirements.

DEFAULT LOCAL RULE
If an axis term is used only to identify the disease/population to which another eligibility predicate applies, treat that axis term as scope by default.
Split it only when the current target independently requires that axis as a coordinate assertion.

CONFIRMATION RULE
Histologic, cytologic, pathologic, or documented confirmation normally belongs to the diagnosis proposition.
Split confirmation only when the confirmation evidence/method itself is independently required as an eligibility condition.

STAGE RULE
Stage subgrades that jointly define one stage category remain one stage unit.

CRITERION-LOCALITY
Do not use repetition or absence in neighboring criteria to decide the local split.
Cross-criterion duplication/deduplication is outside Stage 1.

DO NOT:
- create a diagnosis child solely because a disease name appears as the scope/object of another predicate;
- create a separate confirmation child solely for words such as "histologically confirmed" or "documented diagnosis".

======================================================================
H3. LIST / COVERAGE CHECK
======================================================================

For any list, determine whether named items exhaust the parent eligibility meaning.

OPEN / NON-EXHAUSTIVE
If residual parent scope remains:
- do NOT split named examples solely because they are recognizable concepts.

Typical signals:
- e.g.
- such as
- non-exhaustive including
- etc.

CLOSED / OPERATIONALLY EXHAUSTIVE
If the list fully defines the alternatives in the current target:
- items may become children when they are independently eligibility-determinative.

Typical signals:
- any of the following
- explicitly complete numbered alternatives
- wording that fully operationalizes the parent requirement

OPERATIONAL-CONTENT TIEBREAKER
Item-specific temporal, numeric, grade, treatment, or evidence constraints are strong evidence that a named item carries independent operational content.
They do NOT by themselves prove that the list is closed.

If the list remains open/non-exhaustive after this check:
- KEEP the broad parent meaning as one Stage-1 unit at the current level;
- preserve item-specific temporal/value/status detail downstream on the relevant Criterion→Concept relations;
- DO NOT force overlapping named-item children.

DO NOT create a redundant broad residual-umbrella child solely to preserve open-list scope.

======================================================================
H4. ASSIGN STRUCTURE TYPE
======================================================================

Choose exactly ONE label at the current hierarchy level.

none
- one valid eligibility proposition remains.

composite_split
- two or more independent propositions;
- no true umbrella.

macro_aggregate
- two or more independent propositions;
- a true umbrella/wrapper exists;
- children collectively operationalize the umbrella;
- no hidden residual pass/fail meaning remains in the umbrella.

nested_exception
- the target contains a true carve-out, waiver, or exception to a broader main rule.

EXCEPTION TEST
Use nested_exception when removing the exception phrase restores a broader main rule and the phrase relaxes/waives that rule.

DO NOT classify "without X" as an exception automatically.
If absence of X is itself required, it is an ordinary negative requirement.

DO NOT label a phrase as an exception when the case it describes falls outside the scope of the main rule.
A phrase that only clarifies what the main rule never covered is scope clarification (H0), not a carve-out.
The excepted case must be something the main rule, read alone, would have prohibited or required.

CONDITIONAL ALLOWANCE
"allowed/permitted if Y" is an exception/waiver when Y changes the eligibility of an otherwise restricted state X.
Ordinary optional language such as "may also have received..." is not an exception.

BRANCH-SPECIFIC EXCEPTION
If an exception modifies only one branch of a larger composite:
1. split the top-level branches first;
2. keep the root composite/macro structure;
3. preserve the dependent exception text inside the affected branch's propagated TARGET_SEGMENTS;
4. mark that branch for recursion;
5. annotate the branch as nested_exception on the recursive pass.

Exception spans are NOT child Criterion nodes and are NOT recursively split.

======================================================================
H5. CHILD LOGIC
======================================================================

child_logic is REQUIRED for:
- composite_split
- macro_aggregate

Interpret "holds" as:
THE CHILD CONDITION IS TRUE AS WRITTEN IN THE CRITERION,
not "the patient is ultimately eligible".

AND
- all required/applicable child conditions must hold for the parent criterion as written to hold.

OR
- any one child/path is sufficient for the parent criterion as written to hold.

APPLICABLE-BRANCH SEMANTICS
For a conditional branch that applies only when its corresponding prior event/state exists:
- AND means every APPLICABLE branch must satisfy its requirement;
- a branch whose antecedent does not apply imposes no requirement and is not treated as a failed child.

This defines criterion logic only. Stage 1 does not perform patient-level eligibility evaluation.

For none and nested_exception:
- child_logic = null

DO NOT infer child_logic from:
- inclusion vs exclusion type
- surface "and/or"
- punctuation

Do not flatten mixed logic.
Represent A AND (B1 OR B2) across recursive levels.

======================================================================
H6. RECURSION
======================================================================

This call handles ONE hierarchy level only.

Every generated child is conceptually re-evaluated under H0-H6.

Set:
- needs_recursion = true only when an explicit next-level non-none structure remains;
- recursion_targets = child IDs that require another Stage-1 pass.

For nested_exception:
- only the main content may recurse;
- use recursion_targets = ["main"] when needed;
- exception spans never recurse.

If no lower-level non-none structure remains:
- needs_recursion = false
- recursion_targets = []

recursion_targets is NEW v1.3 pipeline-control metadata.
It is NOT an ontology property and was not present in the historical 113-item v1.2.2 adjudication records.

======================================================================
CROSS-CUTTING OUTPUT RULES — CANONICAL X1-X7
======================================================================

X1. CURRENT-TARGET / TEXT-SPAN FIDELITY

ROOT_CRITERION_TEXT
- full original criterion
- read-only interpretation context

TARGET_SEGMENTS
- one or more exact source segments currently being annotated
- all output spans must be drawn only from these segments

At the root pass:
- TARGET_SEGMENTS normally contains the full criterion.

At a recursive pass:
- TARGET_SEGMENTS contains only the child/main material intentionally propagated from the parent level, including any dependent branch-specific qualifier/exception that must remain available.

PARENT_CONTEXT
- null at the root pass.
- at a recursive pass, a JSON object supplied by the pipeline:
  {"parent_decision": "...", "parent_child_logic": "AND | OR | null", "current_child_id": "a | b | ... | main", "sibling_spans": {"<child_id>": ["..."]}}
- use it only to recover shared meaning (e.g., a subject or qualifier carried by a sibling). Never copy sibling_spans text into your output.

TEXT-SPAN RULES
- text_span MUST be an array of one or more strings.
- EVERY output segment MUST be a verbatim contiguous substring of ONE current TARGET_SEGMENT.
- A single child may contain multiple text_span segments.
- Different text_span segments of the same child MAY come from different TARGET_SEGMENTS.
- NEVER synthesize, normalize, paraphrase, or concatenate non-contiguous source wording into one segment.
- NEVER import new text from elsewhere in ROOT_CRITERION_TEXT if it is outside current TARGET_SEGMENTS.

X2. SHARED EXPRESSIONS / QUALIFIER SCOPE

- Do not duplicate a shared clinical entity solely to make children grammatical.
- Repeat a shared dependent qualifier in every child it semantically modifies.
- A child may be grammatically incomplete if ROOT/PARENT context supplies shared meaning.

Syntactic placement is a default cue, not a hard rule:
- qualifier outside a coordination -> evidence that it may modify all branches;
- qualifier inside one conjunct -> evidence that it may modify only that branch.
Eligibility meaning overrides the cue.

X3. EXCEPTION-SPAN BOUNDARIES

- when an explicit trigger exists, include the complete trigger phrase from its first word;
- for a triggerless parenthetical exception, select the exception content itself and do not add enclosing parentheses solely because they surround it;
- multiple sibling exception spans may attach to one main rule.

X4. COHORT SCOPE

- cohort difference alone is NOT a split trigger;
- split only when cohort-specific eligibility content differs;
- record cohort_scope only when the criterion text itself limits applicability;
- copy cohort labels verbatim from TRIAL_HAS_COHORTS;
- do not infer cohort_scope from arm metadata alone;
- for none / nested_exception, top-level cohort_scope may describe the current Criterion;
- for composite_split / macro_aggregate, top-level cohort_scope MUST be null and scope belongs on the relevant child Criterion(s);
- if the current Criterion/child applies to all cohorts, use null in the fixed JSON transport; omit the ontology property during serialization.

X5. BROAD ADEQUACY / ASSESSMENT / EXTERNAL DELEGATION

- broad adequacy statement without concrete subrequirements -> none
- assessment/test method without independent pass/fail content -> keep with requirement
- substantive thresholds delegated only to IB/Table/appendix -> none at this text level; note delegation
- explicit local thresholds -> evaluate normally

X6. CONCEPTUAL QUERYABILITY / EVIDENCE SOURCE

- base Stage-1 units on conceptual eligibility decisions;
- independent documentation in different standard clinical sources is supporting evidence, not a sufficient split rule;
- do not use site-specific EMR-field availability as a structural rule.

X7. CRITERION-LOCAL DECOMPOSITION

- annotate only the current target;
- do not import a neighboring criterion's text as a child span;
- do not suppress a local requirement because it appears elsewhere in the protocol;
- cross-criterion grouping/deduplication is outside Stage 1.
